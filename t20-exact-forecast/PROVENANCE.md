# Provenance and attribution

**t20-exact-forecast · Siddharth Shashank Kumar · September 2026**

This note distinguishes the task created for this exercise from the data, methods, software and assistance used to build it.

## What was created for the exercise

The original contribution is the task scenario and its implementation: a synthetic Twenty20 league with invented identities, public mechanics and hidden skill values; a reusable forecasting interface; generated public and held-out worlds; comparison forecasters; a Harbor package; a programmatic verifier; an oracle; and the experiments recorded in this repository.

The task was built for this take-home. It is not a direct port of SWE-bench, Terminal-Bench, a public CTF, Kaggle notebook, coding challenge, public benchmark task, public issue or prior Collinear task. This is an account of its creation, not a claim that an exhaustive search found no related forecasting problem.

Two earlier candidate ideas appear in the decision history. They are not included as additional submitted tasks. The zip contains one task directory.

## External data

The simulator's aggregate calibration constants were derived from the [Cricsheet IPL archive](https://cricsheet.org/downloads/), maintained by [Stephen Rushe](https://cricsheet.org/about/). The development records report 1,243 matches and 295,557 deliveries.

**Contains information from Cricsheet, made available under the [Open Data Commons Attribution License 1.0](https://opendatacommons.org/licenses/by/1-0/).** Attribution also appears in `league/calibration.json` and the agent handbook.

No raw Cricsheet rows are redistributed in the task. The shipped league histories are generated from the calibrated simulator, with invented players, teams and venues. The original archive is not committed, and its download hash was not recorded. Consequently, the committed task is runnable without the archive, but exact reconstruction of the original calibration download is not established.

The task was designed and built with Claude, and AI assistance was used to organize, edit and check the documents. Codex assisted with the documentation, figure redraws, packaging, transcript audit and v0.1.1 verifier/environment changes. The fresh validation and model-evaluation status are recorded in [VALIDATION.md](VALIDATION.md). Unaided authorship is not claimed.

The author remains responsible for the design and submission. AI-assisted task creation can introduce bias. An isolated agent environment, same-family failures and cross-family passes provide useful context, but they do not establish that the benchmark is free of design bias.

## Evidence preservation

Original model jobs and diagnostic logs are retained. Known redaction of the literal token `true` is restored in memory for evidence inspection, or in a temporary copy for an explicitly recorded artifact replay; archived source records are not rewritten. The original runtime manifest is preserved. A separate revision manifest identifies 109 unchanged historical files, nine revised files and one added Compose file in the 119-file v0.1.1 runtime. Data, engine, oracle and numerical scoring inputs are unchanged; verifier behavior, environment controls and agent-facing disclosures are explicitly versioned.

Historical v0.1.0 model trials, current-version controls, archived-program replays and fresh model trials are distinct evidence types. Replaying an archived program does not show how a new agent would respond to the corrected handbook. The earlier PDF and working notes remain historical artifacts; the current Markdown report follows the canonical assignment and states the present limitations.
